# 매매기록 이미지 등록

사용자가 MTS 매매 체결/주문 내역 스크린샷을 첨부하며 기록을 요청하면 다음 순서로 처리한다.

## 절차

1. **이미지 읽기**: Read 도구로 첨부된 이미지를 읽어 종목명, 종목코드(있으면), 매수/매도 구분, 수량, 체결단가, 체결일자를 추출한다. 일자가 이미지에 없으면(예: "오늘 체결"만 표시) 사용자에게 정확한 날짜를 확인한다.
2. **계좌 확인**: 아래 명령으로 계좌 목록을 조회하고, 어느 계좌의 거래인지 사용자에게 확인한다 (이미지만으로 계좌를 단정하지 않는다).

   ```
   node .claude/skills/_lib/listAccountsCli.mjs
   ```

3. **파싱 결과 확인**: 추출한 매매기록(계좌/종목/매수·매도/수량/단가/일자)을 사용자에게 보여주고 확인받는다. 특히 매수/매도 구분과 수량·단가는 오인식 시 holdings가 잘못 계산되므로 반드시 확인 단계를 거친다.
4. **등록**: 확인이 끝나면 아래 스크립트로 등록한다. 이 스크립트는 `trades`에 insert 후 자동으로 `holdings`를 재계산한다(매도 시 `realized_pnl`도 함께 계산됨).

   ```
   node .claude/skills/_lib/insertTrade.mjs "<accountId>" "<ticker>" "<name>" <buy|sell> <quantity> <price> <YYYY-MM-DD> ["memo"]
   ```

5. **결과 보고**: 스크립트가 출력하는 재계산된 보유수량/평단가를 그대로 사용자에게 전달한다. 웹 대시보드(`/`, `/trades`)에서도 바로 확인 가능하다고 안내한다.
6. **Notion 갱신**: 이번 세션에 Notion 커넥터(MCP 도구, `mcp__claude_ai_Notion__*`)를 사용할 수 있으면 아래를 수행한다. 사용할 수 없으면(권한 없음/연결 안 됨) 이 단계는 건너뛰고 사용자에게 Notion은 갱신하지 못했다고 알린다.

   a. 최신 포트폴리오 요약을 계산한다.

      ```
      node .claude/skills/_lib/computePortfolioSummary.mjs
      ```

      출력은 `totalValue`(총평가금액), `totalCost`(총매수원가), `profitLoss`/`profitLossRate`(평가손익), `usdKrwRate`(적용 환율), `accountBreakdown`(계좌별 평가금액, 내림차순), `tickerBreakdown`(종목별 평가금액, 내림차순), `growth`(최초 기록 대비 성장률 — 데이터가 아직 하루뿐이면 `null`, 30일 이상 쌓였으면 라벨이 "약 N개월 전(YYYY-MM-DD) 대비"로 자동 전환)를 포함한다.

   b. **"주식 포트폴리오 현황" 페이지**(`398bb6d2-00d0-8174-8970-cc2d00c5348c`)를 `notion-update-page`의 `replace_content`로 전체 재생성한다. 형식은 기존 페이지 구조(전체 요약 표 → 계좌별 비중 표 → 종목별 비중 상위 10개 표 → 보유 계좌 목록 → 참고)를 그대로 따르되, 이번 계산 결과로 숫자를 교체한다. `growth`가 `null`이 아니면 전체 요약 표 아래에 성장률 한 줄을 추가한다(예: "약 1개월 전(2026-06-09) 대비 +6.2%"). `growth`가 `null`이면 이 줄은 생략한다(데이터가 아직 하루뿐이라 의미 있는 성장률이 없음).
   c. **"대시보드" 페이지**(`396bb6d2-00d0-81d3-a815-cd2ce11c278b`)의 자산현황 표에서 아래 5개 행을 `notion-update-page`의 `update_content`(search-and-replace)로 갱신한다. 비고 칸은 "주식 포트폴리오 연동(자동)"으로 유지한다.

      | 대시보드 행 | 매핑 |
      |---|---|
      | 해외증권계좌 | `accountBreakdown`에서 "메리츠증권 해외주식" |
      | 국내증권계좌 | `accountBreakdown`에서 "삼성증권 국내주식" |
      | ISA | `accountBreakdown`에서 "미래에셋 ISA" (다른 증권사 ISA가 추가되면 합산) |
      | 연금저축 | `accountBreakdown`에서 "삼성증권 연금저축" + "미래에셋 연금저축" 합산(계좌명에 "연금저축"이 포함된 모든 항목) |
      | 퇴직연금/IRP | `accountBreakdown`에서 계좌명에 "IRP"가 포함된 모든 항목 합산 |

      계좌명 매핑에 없는 새 계좌(신규 증권사 등)가 등장하면 자동으로 넘겨짚지 말고 사용자에게 어느 행에 포함시킬지 확인한다.
   d. 두 페이지 모두 갱신 완료 후, 결과 보고에 "Notion도 최신 상태로 갱신했습니다" 한 줄을 추가한다. 갱신 중 오류가 나면(페이지 ID가 바뀌었거나 커넥터 연결이 끊긴 경우 등) 매매기록/holdings 등록 자체는 이미 성공했으므로 롤백하지 않고, 사용자에게 Notion 갱신만 실패했다고 알린다.

## 주의사항

- 매도 수량이 현재 보유수량보다 많은 등 비정상적인 값이면 등록 전에 사용자에게 알린다 (recalcHolding은 수량이 0 이하가 되면 holdings 행을 삭제하므로, 잘못된 매도 기록은 보유종목을 통째로 지울 수 있다).
- 여러 건을 한 번에 등록할 때는 반드시 이미지에 보이는 시간/일자 순서대로 하나씩 처리한다 (평단가 계산이 순서에 의존하므로).
- `.env.local`의 Supabase 자격증명을 사용하므로 프로젝트 루트(`D:\클로드`)에서 실행해야 한다.
- Notion 갱신(6단계)은 이 Claude Code 세션에서 Notion 커넥터를 통해서만 가능하다. 배포된 웹 대시보드나 `.mjs` 스크립트 자체는 Notion에 접근할 수 없다 — 그래서 이 갱신은 "완전 자동"이 아니라 "이 스킬을 실행하는 세션마다 자동으로 수행"되는 것이다.
- 두 Notion 페이지의 ID는 하드코딩되어 있다. 페이지가 삭제되거나 다른 곳으로 옮겨지면 이 스킬 문서의 ID도 함께 갱신해야 한다.
