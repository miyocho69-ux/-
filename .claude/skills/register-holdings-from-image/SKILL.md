# 보유현황 이미지 등록

사용자가 증권사 앱(MTS/HTS)의 보유종목 화면 스크린샷을 첨부하며 등록을 요청하면 다음 순서로 처리한다.

## 절차

1. **이미지 읽기**: Read 도구로 첨부된 이미지를 읽어 종목명, 종목코드(있으면), 수량, 평단가를 각 행마다 추출한다. 종목코드가 이미지에 없으면 종목명만으로 유추하지 말고 사용자에게 확인한다.
2. **계좌 확인**: 아래 명령으로 등록된 계좌 목록을 조회하고, 어느 계좌에 등록할지 사용자에게 확인한다 (이미지만으로 계좌를 단정하지 않는다).

   ```
   node .claude/skills/_lib/listAccountsCli.mjs
   ```

3. **파싱 결과 확인**: 추출한 종목/수량/평단가 목록을 표로 정리해 사용자에게 보여주고, 등록 전에 반드시 확인을 받는다 (OCR 오인식 가능성이 있으므로 이 단계를 생략하지 않는다).
4. **등록**: 확인이 끝나면 종목별로 아래 스크립트를 실행해 upsert한다.

   ```
   node .claude/skills/_lib/upsertHolding.mjs "<accountId>" "<ticker>" "<name>" <quantity> <avgCost>
   ```

   - `accountId`는 2번에서 확인한 계좌의 UUID
   - `ticker`는 종목코드(국내는 6자리 코드, 해외는 티커 심볼)
   - `quantity`, `avgCost`는 숫자만 (콤마/원화기호 제거)

5. **결과 보고**: 등록된 종목 수와 각 종목의 최종 quantity/avgCost를 요약해 알려준다. 웹 대시보드(`/`)에서도 바로 확인 가능하다고 안내한다.

## 주의사항

- 이 스킬은 `holdings`에 **직접 upsert**한다 (매매기록을 거치지 않음) — 최초 보유현황 등록이므로 이력이 없는 스냅샷 등록이다. 이후 매매는 `log-trade-from-image` 스킬이나 웹의 매매기록 폼을 사용해야 `trades`에 이력이 쌓인다.
- `.env.local`의 Supabase 자격증명을 사용하므로 프로젝트 루트(`D:\클로드`)에서 실행해야 한다.
- 이미지 화질이 나쁘거나 표가 잘려 일부 항목이 불확실하면, 그 항목은 등록하지 말고 사용자에게 재확인을 요청한다.
